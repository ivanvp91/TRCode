# Исправления после аудита TRCode

Дата: 4 октября 2026. Это результат изменений в рабочем репозитории; исходный аудит и JSON воспроизведений описывают состояние **до исправлений**.

## Папки media

Каждая генерация автоматически создаёт уникальную рабочую папку:

```text
media/<image|audio|video>-<timestamp>-<random-id>/
  manifest.json
  tmp/
  scenes/
  output/
```

Манифест хранит модель, запрос, параметры, состояние, стоимость, пути результатов, проверки качества и идентификатор задания видео. Локальные изображения, реально отправленные провайдеру, сохраняются в `tmp/reference-*` с SHA-256. Удалённые ссылки отмечаются как ссылки: какие именно байты скачал провайдер, локальный клиент подтвердить не может.

Для монтажа и нескольких сцен добавлен `prepare_media_workspace`: агент получает пути **до** создания скриптов и промежуточных файлов. Общие инструкции и video mode требуют складывать scratch в `tmp`, сцены в `scenes`, результаты в `output`. Аргумент `workspace` объединяет сценовые генерации в одну папку. Это правило для планирования агентом; shell остаётся полноценным инструментом с подтверждением и технически может создавать файлы в других местах.

По умолчанию отдельные картинки, звук и видео больше не записываются в корень проекта. Явный `out` сохраняет возможность экспорта по указанному пути. Имя получает расширение настоящего формата. Существующие результаты не перезаписываются; известный конфликт обнаруживается до оплаты, конкурентный конфликт — при сохранении.

## Дополнительные изменения

- `resume_media` продолжает ожидание/загрузку существующего видео и восстанавливает удержанные image/audio без нового POST. Завершённое видео можно восстановить после Esc или ошибки загрузки. Неизвестный результат POST без полученного job ID фиксируется как `submission_unknown`, а не автоматически повторяется.
- Платные запросы учитываются в стоимости сессии. Отсутствующая стоимость отмечается неизвестной. Когда провайдер сообщает сумму, запись того же задания обновляется, не увеличивая счётчик второй раз. Реальная стоимость chat API тоже имеет приоритет перед оценкой по токенам.
- Sharp действительно декодирует изображения. `read_image` строит ограниченный PNG preview с сохранением alpha, поддерживает crop и metadata-only. Проверки результата генерации сравнивают размер, пропорции, формат и прозрачность с запросом. Несоответствие сохраняет оплаченный результат и возвращает ошибку качества; новая генерация автоматически не запускается.
- Речь сохраняется вместе с полученным transcript и PCM-показателями. Различие transcript с исходным текстом, тишина и заметный clipping показываются пользователю. Сравнение transcript подтверждает только текст, заявленный провайдером, и не заменяет независимое распознавание речи.
- Откат пропускает пользовательские изменения и сохраняет записи о неприменённом восстановлении. Ошибка snapshot не превращается в удаление файла. Для файлов сверх прежнего лимита snapshot 4 MB автоматический undo остаётся недоступен.
- Сессии сохраняются через временный файл и rename с предыдущей копией `.bak`. При повреждении текущего JSON загрузка использует backup. Ошибки диска видимы через сообщение и `saveError`.
- Оркестрация проверяет зависимости и циклы до выполнения, пропускает этапы с неуспешными обязательными зависимостями и считает успехом только нормальное завершение. Отказ разбора плана больше не учитывает его стоимость дважды.
- MCP имена получают hash при sanitizing/truncating; неизвестные или изменяющие состояние tools требуют write permission. Read-only hint влияет на класс разрешений, но не является криптографическим доказательством поведения внешнего сервера.
- Бюджет запроса учитывает system prompt и полное описание/schema tools; vision получает приблизительную отдельную оценку вместо tokenization base64. Footer обновляется при смене модели. Чтение больших текстов с offset/limit потоковое; regex backtracking в grep имеет deadline.
- Goal прекращает автоматическое продолжение после ошибки API или незавершённого agent run. Integration test действительно выдаёт HTTP 400 и ждёт готового input consumer, вместо случайной потери ввода между UI состояниями. Brain test ждёт готовности сервера по HTTP.

## Воспроизводимость

```powershell
npm install
npm run build
node test/audit-regression-test.mjs
npm test
```

53 новые проверки проходят на локальных mock-провайдерах и собственных временных файлах. Окончательный полный прогон после fresh build: **62/62 suites прошли**, включая 53/53 audit regression; первый полный прогон также прошёл. Проверены `git diff --check` и npm package dry run. README описывает новые контракты. `scripts/audit-repro.mjs` теперь запускает post-fix regression suite; исходный код воспроизведения сохранён в `repro-source-before-fixes.txt`, а первоначальные результаты — в `reproductions-2026-10-04.json`.

Текущая установленная команда `trc` является npm junction на этот репозиторий; пересобранный `dist` используется при следующем запуске. Работающий процесс нужно перезапустить.

## Что не подтверждено как «идеально»

Живые платные запросы и слепое сравнение художественного качества с конкурентами не проводились. Local tests подтверждают контракт, отмену, сохранение и recovery, но не содержимое ответа реальных облачных моделей. Таблица providers остаётся ограниченной возможностями соответствующих API; отсутствующие функции вроде полноценной транскрипции входных файлов и timeline editor не появились сами собой.

MP4 проверяется на сигнатуру контейнера и ограничение размера, без полного декодирования всех кадров и дорожек. FFmpeg/ffprobe в текущей среде не обнаружены. Для codec QA, фактической длительности/fps/звука, видеопревью, монтажа и независимой оценки audio нужен следующий этап с реальными media fixtures и декодером. BMP поддерживается как metadata-only; Sharp preview ориентирован на PNG/JPEG/GIF/WebP.

`run_code` ограничен стандартным JS и SDK, без секретов окружения и native imports; дополнительно включены Node permissions. Это несколько барьеров защиты, не полноценная OS sandbox для враждебного кода. Одновременная замена путей внешним процессом между проверкой и commit также не эквивалентна устранению всех файловых TOCTOU на уровне ОС.

Чтобы обоснованно утверждать «лучше других», остаются одинаковые задачи и модели, реальные provider runs, независимые проверки результата, замеры цены/latency и слепые оценки. Матрица такого benchmark приведена в исходном аудите. Эти ограничения нельзя скрывать за зелёными тестами.
