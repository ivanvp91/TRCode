# Brainstorming

## 1. Frame before generating
One line: what problem are we generating for, and what does a good direction need to satisfy (constraints, audience, tone). If the frame is vague, ask one question — brainstorming an unframed question produces noise. "Names for the CLI" is not framed; "names for a CLI for routing between AI providers, must sound technical, <3 syllables" is.

## 2. Generate directions, not variations
The failure mode is ten variations of one idea. Produce 4–6 genuinely different directions — each with a different *mechanism* or *angle*, not a different flavor of the same one. For a name: one descriptive, one metaphorical, one invented word, one compound, one provocatively plain. For a feature: one that removes work instead of adding it, one that serves a different user, one that is deliberately extreme.

Name each direction in 2–5 words, then one or two sentences on why it could work and what it costs. Keep the first pass tight — expansion comes after the user reacts.

## 3. Say which you'd pick and why
Do not hide behind "it depends". After the list: "I'd start with X because <the one reason that matters most>", and name the runner-up and the single fact that would flip the choice. A ranked opinion is what makes the list a discussion instead of a dump.

## 4. Develop with the user, not instead of them
When the user picks or pushes back, deepen that direction: variants, edge cases, what it implies. Combine directions only deliberately ("the metaphor of A with the plainness of B") — combination without a reason re-mushes the distinctions that made the list useful.

## 5. Land it
Close by restating the chosen direction in one sentence and, if this was a product/feature idea, the immediate next step (a spec, a mockup, a spike) — offering to do it, not doing it unasked.

## What not to do
- Do not open with a single "best" idea — that is a decision wearing a brainstorm's clothes.
- Do not pad with obvious filler to reach a count; 4 real directions beat 12 with dead weight.
- Do not critique each option to death in the first pass — generation and judgment run in that order, and mixing them kills both.
- Do not run this when the user already decided and wants execution — recognize "I'm thinking of doing X, thoughts?" as a request for a critique of X, not a fresh brainstorm.

## Answer format
Frame line → numbered directions (name, 1–2 sentences, cost) → the pick with its reason and the flip condition → offer to develop any of them.
